# Financial SDLC selection — project-authored engineering policy

The ranked policy uses sixteen explicitly rated factors: change frequency, security risk, uncertainty, verification, continuous delivery, stakeholder availability, legacy complexity, approval formality, requirement stability, regulatory criticality, project complexity, system size, budget constraint, schedule pressure, formal verification and failure consequence.

Agile suits frequent feedback and changing scope; DevSecOps adds continuous verification and deployment controls; Spiral emphasizes uncertainty and risk prototypes; V-Model connects specification levels with test levels; Waterfall emphasizes sequential baselines. Hybrids must explain how their practices combine. Scores are heuristic suitability indices rather than probabilities or validated expert accuracy.

Financial workflows should allocate applicable threat modelling, transaction-integrity/reconciliation tests, data lineage, security testing, legal applicability review, independent approval, deployment and rollback evidence to actual phases. Do not invent budgets, dates or regulator mandates. Product owners approve requirements; architect, security, legal, project manager and operations approve relevant adoption/release decisions independently.
